# 系统化调试

1. 保存原始命令、工作目录、环境、输入、Exit Code、完整 stdout/stderr 和最小 Artifact Digest；缺少这些字段时先补诊断，不猜测。
2. 明确失败发生在入口解析、构建、部署、Runtime 启动、状态恢复、业务动作还是验证阶段，从错误边界向上游追踪输入与状态。
3. 列出相互排斥、可证伪的根因假设，并写明每个假设成立或不成立分别会观察到什么。
4. 每个 Attempt 只验证一个假设，优先使用最小复现、二分范围、边界对照、历史 Fixture 或临时观测。
5. 找到根因后先建立能够复现原始失败的回归测试，再做最小修复并用同一测试证明闭环。
6. 连续失败时记录已淘汰假设并更换策略与 Relevant Input；不得原样重试。Budget 耗尽时报告完整证据。
