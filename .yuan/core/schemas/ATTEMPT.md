# Yuan Core Attempt Schema

**Schema ID:** `yuan.attempt/v1`  
**Last Updated:** 2026-07-31

## Structure

An Attempt records **one selected Proposal that has been executed** (or is about to be executed). It links the proposal to its execution outcome and resulting evidence.

Only proposals in state SELECTED may be converted into Attempts. The conversion is atomic: once an Attempt exists for a Proposal, the Proposal becomes NOT_SELECTED or SUPERSEDED depending on context.

## Required Fields

| Field | Type | Description | Example |
|-------|------|-------------|---------|
| `attempt_id` | string | Format: A-XXXXXXXX | `A-000018` |
| `source_proposal` | string | Reference to originating Proposal ID | `P-000042` |
| `work_revision` | integer | Work revision at time of attempt creation | `7` |
| `base_artifact_hash` | string | SHA256 of artifact before attempt execution | `sha256:a1b2c3...` |
| `strategy_fingerprint` | string | Normalized fingerprint from selected proposal | `sha256:def456...` |
| `status.phase` | string | Phase: prepared / executing / completed / failed | `prepared` |
| `status.result` | null \| string | Final reducer result (set after completion) | `null` during preparation |
| `execution.action_refs` | array[string] | Platform-specific action identifiers | `["goal:xyz123"]` |
| `execution.resulting_artifact_hash` | null \| string | SHA256 after attempt (post-execution) | `null` until complete |
| `verification.evidence_refs` | array[string] | Evidence IDs generated by this attempt | `[]` initially |
| `verification.reducer_result` | null \| string | Reducer output: WAIT_AUTH/BLOCKED/BUDGET_EXIT/COMPLETE/CORRECT/CONTINUE | Set after evidence collection |

## Lifecycle Transitions

```
SUBMITTED (Proposal) → SELECTED → Prepared → Executing → Completed → Validated → State Updated
      ↓                                      ↓
  ADMIT_REJECTED                       FAILED (retries or CORRECT path)
```

At each transition, a Journal entry MUST be written (see `schemas/JOURNAL.md`).

## Atomicity Guarantees

Each Attempt represents exactly **one atomic change intent** as declared in the source Proposal's `atomic_change_set.intent`. The platform must ensure either all changes in target_scope are applied successfully, or none are applied.

If partial application occurs, the Attempt fails with side_effect_class determining recovery strategy.

## Artifact Hash Tracking

- `base_artifact_hash`: Snapshot of affected files BEFORE attempt
- `resulting_artifact_hash`: AFTER successful completion

If these differ, the Attempt modified content as expected. If identical but status is completed, verify whether this was intentional (e.g., no-op validation).

## Example Attempt Record

```yaml
schema: yuan.attempt/v1

attempt_id: A-000018
source_proposal: P-000042
work_revision: 7
base_artifact_hash: sha256:d9f8e7c6b5a4z3x2v1u0t9s8r7q6p5o4n3m2l1k0j9i8h7g6f5e4d3c2b1a0
strategy_fingerprint: sha256:9a8b7c6d5e4f3a2b1c0d9e8f7a6b5c4d3e2f1a0b9c8d7e6f5a4b3c2d1e0f

status:
  phase: prepared
  result: null

execution:
  action_refs:
    - goal:exec-backend-dev-token-rotation-001
  resulting_artifact_hash: null

verification:
  evidence_refs: []
  reducer_result: null

journal_entries:
  - J-000001  # attempt_created
  - J-000002  # phase_changed: preparing→executing
  - J-000003  # phase_changed: executing→completed
  - J-000004  # phase_changed: completed→validated
